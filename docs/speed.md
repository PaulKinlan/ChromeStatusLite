# Gate speed and coverage

- Fast budget: <=60 s. `tools/fast-gate.sh` maps changed paths (including deletions) to offline route/client suites; unmapped paths fail. Deleting a mapped path reruns its former suites so an unsafe removal fails; deleting a required test suite fails until the gate's suite list is updated. Handler/static style/config changes select all suites; renderer changes select only suites that load the changed module. A zero-diff tree still runs all suites. No server starts on import. Dependencies are cached (`--cached-only`), so an uncached checkout fails rather than quietly reaching the network. Feed and API-version changes select their owned `feed_test.ts` and `api_version_test.ts` suites **plus** `handler_test.ts`: retained cross-route assertions check feed outage notices, milestone range requests and JSON error-detail redaction. Index, diff, deprecations and feature changes likewise select `handler_test.ts` for the cross-route failure policy still held there. Breaking/origin-trial changes select `timeline_test.ts`, which already owns their failure assertions. Static HTML changes select `shell_test.ts` (page landmarks/headings/nav) and `handler_test.ts` (HTTP/static policy); `src/flora.ts` changes select the route suites and standalone `flora_test.ts`, but not the unrelated client suite. The wiki modules (`src/routes/wiki.ts`, `src/routes/wiki-topic.ts`, `src/lib/wiki.ts`) map to their own focused suite (`tests/wiki_test.ts`); the tagger is pure and the route tests use the fixture client, so no wiki test touches the network.
- The fast gate then ALWAYS runs `tests/http_smoke_test.ts` in a second, wider-sandboxed `deno test` invocation (same permissions as the full gate's smoke run). A changed test file is only 'placed' in fleet-check coverage by its own execution, and shared modules (`src/handler.ts`, `tests/fixture.ts`) count the smoke suite as a covering candidate — without it every fast verdict reported PARTIAL coverage (chrome-status-lite-tor). It is offline, fixture-backed and ~4 s (three browser launches: two `--dump-dom` visits and one DevTools-driven style probe). The smoke suite also imports `main.ts`, whose `Deno.serve` call sits behind an `import.meta.main` guard so the deploy entrypoint is genuinely loaded (module-evaluated) on every gate without binding a port.
- Coverage attribution is honest about what is exercised (chrome-status-lite-74e): `.fleet/coverage-contract.json` declares suite placement ONLY for paths with a real transitive import into the executed suites (`src/flora.ts`, `src/stream-utils.ts`, `src/ui-components/*`) — a declared-but-never-loaded path turns a truthful PARTIAL into a false KNOWN. The gate harness itself is covered by real execution: when `tools/*`, `.fleet/*` or `tests/gate_test.ts` changes, a third `deno test` invocation runs `tests/gate_test.ts`, which drives both gate scripts in scratch git repos with a stubbed `deno` and pins the contract to the fast-gate mapping. The same harness pins the shared-util mapping (`src/lib/utils.ts`) to the real import graph: every `src/routes` file that imports the util must have its suite inside the util's selection, so a new consumer cannot pass the fast gate uncovered (chrome-status-lite-4li). It also pins route ownership, deleted-suite fail-closed behaviour and the full gate's exact offline suite set. `src/types.ts` was deleted: it was dead, unreferenced code that no suite could ever load.
- Full budget: <=300 s. `tools/full-gate.sh` runs all offline route/client suites (including tests/history_test.ts, with --unstable-kv for the real embedded-KV tests) plus a fixture-backed real HTTP listener, redirect/static/404 checks and a headless Chrome DOM + screenshot check. The HEAD-strip streaming guard in tests/handler_test.ts is deterministic and small (chrome-status-lite-vp3 replaced a 256 MiB `Deno.memoryUsage().rss` threshold probe with a whole-body-API spy: the suite now peaks at ~146 MiB and its handler tests report 0.6-2 s on this VM, and the assertion no longer depends on the host or the GC schedule). The exact offline suite list and the --unstable-kv flag are pinned by tests/gate_test.ts, so dropping a suite or the flag fails the fast gate. The gate-harness suite itself (tests/gate_test.ts) runs only in the FAST gate when tools/*, .fleet/* or gate_test.ts changes - the full gate never runs it. The browser's stylesheet request status is observed at the HTTP listener, with an isolated negative fixture proving that a CSS 404 is caught. Only the merger runs this tier on the merged union.
- First local focused measurement (2026-10-17, Deno 2.9.7, cached dependencies): fast affected set 8 assertions / ~0.5 s Deno reported; HTTP/browser smoke 1 assertion / ~1 s Deno reported. After the stylesheet-negative fixture (review finding chrome-status-lite-8aa), the focused browser test took ~2 s locally (two browser visits). With chrome-status-lite-tor the fast gate always includes the smoke suite: fast total ~2.9 s wall on this VM (chrome-status-lite-2x9 added one more headless-browser visit to that suite for the keyboard focus-ring probe: +~1 s, measured 3 s for the suite's three visits; chrome-status-lite-ci1 added a fourth visit so the same probe page is loaded once under `prefers-color-scheme: dark` as well as the pinned light scheme, measured 4 s for the suite's four visits; chrome-status-lite-0hn replaced those two focus/token visits plus their three-attempt retry loop with a single DevTools-driven probe - forced `:focus-visible` via `CSS.forcePseudoState` and `prefers-color-scheme: dark` emulated on the page - so the measurement no longer depends on the headless window's focus state: three browser launches, measured 3-5 s for the suite on this VM, 8.6 s fast total); gate-tooling changes add `tests/gate_test.ts` (~1 s, scratch git repos, stubbed deno); a `src/lib/utils.ts` change also selects the feed, API version and timeline suites so every route importing the shared util is covered (chrome-status-lite-4li). The ~11 s sample predates the suite split; remeasure the new tree before comparing it with the 60 s fast budget. These are development samples, **not** a fleet-check median. Coord installs host `CHECK_FAST_CMD=bash tools/fast-gate.sh` and `CHECK_CMD=bash tools/full-gate.sh`; remeasure cached PASS samples and use `fleet-budget` before claiming either budget met.
- Route fixture suites are independent and never call upstream. Client fixture injects a fetcher and cache controlled by a local clock; it does not touch the process singleton. Browser creates and closes its own server/profile. No test reads another test's generated files.
